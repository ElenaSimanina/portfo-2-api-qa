# Матрица покрытия API — Portfo 2

## 1. Назначение

Матрица отражает покрытие выбранных сценариев REST API проекта Portfo 2 тест-кейсами и автоматизированными проверками Postman.

В документ включены сценарии авторизации, регистрации, получения данных профиля и обновления токена. Матрица позволяет оценить распределение тест-кейсов по эндпоинтам и увидеть известные ограничения тестирования.

Количество тест-кейсов не является процентом покрытия всего API.

## 3. Автоматизация проверок

Основные сценарии авторизации, регистрации и обновления токена представлены запросами Postman со скриптами `Tests`. Скрипты выполняют автоматизированные проверки ожидаемых результатов.

В папке `Exploratory testing` также находятся исследовательские запросы. Четыре запроса авторизации не содержат скриптов `Tests`, поэтому их выполнение не добавляет автоматизированных assertions в отчёт прогона. Для запроса регистрации с пустым `invite_hash` предусмотрены проверки тела запроса и статуса ответа `201 Created`.

Наличие запроса в прогоне не означает, что для него обязательно выполняются автоматизированные проверки.

## 4. Известные ограничения и вопросы

- **Валидация email при авторизации.** Поведение при передаче email некорректного формата не описано в Swagger. В исследовательских сценариях API возвращает `401 Unauthorized`, выполняя проверку учётных данных без отдельной ошибки валидации формата.
- **Пустой `invite_hash` при регистрации.** Требования не определяют ожидаемое поведение. В проверенном сценарии API возвращает `201 Created`.
- **BUG-001 — тип `invite_hash`.** API принимает числовое значение `invite_hash`, хотя ожидается строковое. Дефект описан отдельно.
- **Telegram Mini App.** Сценарий `POST /api/v1/authenticate/tg_miniapp/` не включён в текущий объём тестирования.

## 5. Связанные артефакты

- `test-report.md` — результаты последнего прогона Postman и описание выявленного дефекта.
- Postman-коллекция `Portfo 2 — QA_Practical` — запросы и автоматизированные проверки.
- BUG-001 — описание дефекта обработки `invite_hash`.

## 6. Примечание к подсчётам

В матрице учтено 47 уникальных описанных тест-кейсов: 42 основных и 5 исследовательских.

Количество тест-кейсов отличается от количества автоматизированных assertions. В последнем зафиксированном прогоне Postman было 160 assertions: 158 успешных и 2 неуспешных. Оба неуспешных assertions связаны с BUG-001.

Эти показатели описывают разные аспекты тестирования и не должны использоваться как взаимозаменяемые метрики.

Матрица отражает рассмотренные сценарии в указанном объёме тестирования и не заявляет о полном покрытии всех эндпоинтов API.
